# 临时插单、审核计分与并行任务

本功能只修改正式 Python/SQLite 服务；旧 Vinext/D1 演示不在本次范围内。

## 规则

- 余文浩使用姓名登录后自动获得管理员权限；进入管理页会复用同一会话，可选择员工、任务标题、预期分钟和验收要求创建临时插单。默认 120 分钟，仅作预期，可调整，无两小时强制截止。
- 普通登记不会产生高优先资格。插单初始为普通，员工点击“标为高优先”后生效。每人最多一个高优先，由 SQLite 唯一索引和事务保证。
- 新高优先接替旧高优先时，旧任务恢复普通，执行状态与耗时不变；替换记录写入 task_events。员工自行暂停、继续、并行、阻塞、解除阻塞。
- 多个任务允许同时计时。暂停与 hb 必须指定任务；旧客户端在只有一个活动任务时可以省略 task_id，有多个时明确拒绝，避免操作错任务。work_get_active 保留旧 task 字段并新增 tasks 列表。
- 提交必须有文字完成说明，网页不提供附件或交付链接。原链接接口兼容保留，不新增文件存储。
- 提交后关闭计时；等待审核不计时。退回进入需修改，保留历史时段，员工重新开始后累加；不自动把等待员工恢复的时间算为工作。
- 审核通过时默认采用员工提交的 `0–10000` 整数自评分，0 也算；负责人可通过“覆盖分数”填写最终得分。平台 AI 建议分同样只允许整数，且不自动转成正式分数。重复审核拒绝。通过后释放高优先标记。
- 员工自评分在提交时必填（0 也算有效），说明可选；负责人通常直接点击“通过验收”采用员工自评分，需要调整时点击“覆盖分数”填写最终分。平台建议仍在负责人请求时生成，且不包含员工自评分。
- 平台仅收到任务标题、类型、交付要求、验收标准、完成说明，无模型业务操作权限。缺少配置或请求失败显示错误，不伪造建议分。重提任务会清除旧建议；返回过程中任务被审核或重提时拒绝写回旧结果。
- 默认评分参考：简单独立成果 1 点、常规 3 点、复杂 5 点、更大范围 8 点以上须说明；不按耗时、返工次数或紧急程度自动加分。最终仍由负责人决定。
- 点数归属上海时区的审核通过日。页面展示每日及近 7 天累计；跨天未完成任务保持可见。父任务只汇总，独立阶段由子任务分别审核，父任务不重复计分。
- 大任务一次验收（2026-09-20 起）：大任务的全部小任务提交待验收后，负责人可在“优先关注”的大任务汇总项看到员工建议总分并一键验收；每个小任务仍按自己的员工自评分分别计分，等价于逐项点“通过验收”。未全部提交时不做整组验收，也不把其中的待验收小任务单独推给负责人；缺少自评分、越权调用和重复验收均被服务端拒绝。
- 历史已完成但未人工评分的任务显示未打分数量，不把历史工时换算值冒充人工评分。原预计点数字段保留用于兼容旧数据，不作为新正式产出统计。

## 2026-09-20 大任务一次验收

新增服务端动作 `owner_review_group`（仅负责人会话可用）：仅在目标大任务的全部小任务都处于“待验收”时通过整组验收，按各小任务自己的员工自评分逐项计分，写入审核通过事件，重复验收与越权调用均拒绝。`task_groups` 汇总新增 `pending_count`、`suggested_points`、`suggested_complete`、`awarded_points`、`ready_for_acceptance`，供负责人看板显示“员工建议总分”并渲染一次验收按钮。

## 2026-09-22 每日一键验收

负责人总览的“优先关注”新增“一键验收全部”：随时可按员工自评分批量通过当前合格的待验收任务。独立任务有有效自评分即可进入批次；大任务只有所有仍在执行的小任务都已提交后才整组进入，缺少或异常自评分的任务继续保留。每项仍分别写入最终得分、完成时间和审核事件，大任务本身不重复计分。

正式 Python 服务新增上海时区每日 23:30 自动验收。当天已由负责人手动处理的任务不会重复处理；定时批次只查看触发时仍待验收的合格任务，每个自然日最多运行一次，服务在 23:30 后重启会补执行当日批次。批次结束后才把日期写入 `board_settings`，失败会重试，避免半批提交或重复计分。
